## Important behavioral distinctions

1. **Motor output / physical arming**: Current FlightCore diagnostic build advertises `motorsDisabled=true`, `motorsArmed=false`; it does not implement motor flight PID. Never represent a diagnostic input ARM as ESC/motor ARM.
2. **RC control claim**: Exclusive authenticated owner/lease; may exist without live frames and without input ARM. A disarmed claimed owner is distinct from an uncontrolled Kit.
3. **Requested input arm**: Browser/Android/PPM user's requested diagnostic state; not authoritative until accepted.
4. **Accepted RC input**: Monotonically sequenced, owner-verified, range-validated frame accepted by firmware, subject to receive/apply freshness.
5. **Simulator run**: Independent virtual motor/physics state controlled by WebApp. Read-only mirrors must never start or arm the Kit.

## Priority-sorted file-level implementation plan — NOT IMPLEMENTED

**P0 protocol + safety tests before writes**: Add pure cross-client fixtures for versioned status/RC schemas and nullable fields. Treat `bootId`, full `kitId`, protocol version, owner, sequence, timestamps and accepted-vs-requested ARM separately. Extend `tools/flight-mode-kit-integration.test.mjs`, `tools/live-inputs.test.mjs`, `tools/udp-rc-contract.test.mjs`, `tools/usb-rc-dashboard.test.mjs`, and `tools/simulator-input.test.mjs`. Preserve 500 ms receiver deadman and 300 ms native input guard; do not remove independent liveness checks.

**P1 firmware mode mutation**: In `FlightCoreNetwork.h` and `FlightCoreClassroom.h` add explicit authorization policy allowing a disarmed *current* diagnostic owner to persist flight-mode metadata; continue to reject unverified STA observers, competing owners, OTA/network busy, and real armed motor state. If future real flight hardware is in scope, a separate verified flight-mode transition safety design and motor-inhibit acceptance gate are mandatory—metadata POST alone is insufficient. Expose `flightModeRevision` / `modeSaved` or equivalent atomic response; retain previous `flightMode` field. Add an authorized USB mode command with a positive ACK and readback (not a naked `ZJRC` frame). Do not send unverified input while saving.

**P2 Android**: In `companion-network.js` and `companion-flight.js`, remove only the overly broad `rcSession` block for safe disarmed owner mode updates; keep owner verification and last-applied mode readback. Distinguish selector enabled state from privileged mode write authorization; always show the actual Kit mode, pending, rejected and simulator-local mode. Ensure disarmed stick preview has an explicitly authorized/claimed lifecycle and expiry; never transmit to a Kit if a different physical owner exists. Preserve separate STOP and LED controls.

**P3 auxiliary channels + decoded telemetry**: Expand native `FlightCoreUdpStream.java`/bridge to accept validated AUX1/AUX2 updates; in `FlightCoreUdp.h` preserve all six accepted channels through `zjRcFrame` or an accepted six-channel record, rather than dropping channels 5/6 when applying 4-axis RC. Add versioned AUX fields to signed `/api/rc/snapshot`, signed HTTP preview and USB serial `ZJRC/ZJTEL` when supported; extend `js/serial-rc-decoder.js`, `js/kit-data-interface.js`, `js/live-inputs.js` to report UNKNOWN where legacy firmware omits them. Keep PPM 8 channels and its independent CH5 arm-switch semantics; no implicit mapping of AUX to LED/motor output.

**P4 shared WebApp mode + monitor**: `js/classroom-kits.js` should route a single capability-checked `setFlightMode` command through currently verified USB, AP, STA or explicitly authorized relay; never create a second auth/ownership system. Update the existing Live Inputs and firmware controls in `index.html` and `lab.html`, with no duplicate selector/poller. Use `js/kit-data-interface.js` for verified monitor path, `js/live-inputs.js` for accepted read-only snapshot; show mode revision/status, channel values, source, age, input arm, LED and motors independently. Preserve Android relay grants.

**P5 simulator-source integration**: Extend `tripod.html`, `js/simulator-input.js` and `js/tripod-page.js` with an explicit verified USB monitoring option and coherent kit mode readback. Distinguish read-only USB input from simulator control source; label the actual transport and sample origin rather than equating `ANDROID` with every remote link. Synchronize to actual Kit flight mode only according to a documented rule that never restarts or silently reconfigures a running virtual PID plant; display a pending/different-mode indicator while running. Keep virtual Run/Stop, PID changes and hardware writes decoupled.

**P6 physical acceptance / release**: Bench test A1 and A2 by USB, AP, STA, Android native, signed WebApp and optional relay; verify release, replay, owner conflict, 500 ms failsafe, USB disconnection, mode boot restore, LED lease, CH5/CH6, PPM signal loss, and simulator freshness. Confirm no motors/ESC power attached for diagnostic firmware tests. Only later consider flight hardware with a separate safety and certification process.
