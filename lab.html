Connection & Security
WebRTC encrypted peer-to-peer connection. Two-Way QR requires no cloud; six-digit code mode uses a public online signaling service and needs Internet. Short-lived QR and code confirmation, one active controller, state sync, ACKs, and heartbeat.
Refreshing the Web App or reopening Android ends pairing. Wi-Fi switch clears stale controller rights; reconnect via a fresh QR. Laptop camera is used only to read the phone response QR.
Both methods work on the hosted GitHub Pages site. Camera mode requires no signaling service. No Camera code mode uses a third-party online PeerJS signaling broker (Internet required on PC and phone). Neither method grants LED control without confirmation.
